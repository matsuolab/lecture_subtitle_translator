# R2 Drop-First 実装計画

> 作成: 2026-04-03
> 目的: 動画をプレイヤーへドロップするだけで、パイプラインが一気通貫で実行されるUXを段階的に実装する。

---

## ゴール

- ユーザー操作は「動画をドロップ」の1アクション。
- 実行中は同一画面で進捗・失敗理由が確認できる。
- 完了後は字幕ブロック編集画面に自動遷移し、結果が即編集可能。

---

## マイルストーン

1. M1: UI骨格
- 動画Drop時に Pipeline Job を開始するフロント実装。
- 右パネルに Pipeline Status を追加（待機/実行中/成功/失敗）。

2. M2: 一気通貫の最小接続
- 既存SRTを入力に使う暫定ルートで、Drop→実行→字幕反映を通す。
- 失敗時リトライとログ表示を実装。

3. M3: 書き起こし実処理接続
- WhisperX（local/remote provider）で字幕生成。
- 生成結果を字幕ブロックへ反映。

4. M4: 翻訳品質とコスト可視化
- 各ステップの処理時間・入力/出力トークン・推定コストを保存。
- 実行結果に品質指標（CPS違反率、42文字超過率）を表示。

## 完了条件（DoD）

- 動画ファイルDrop後、ユーザー操作なしでPipelineが開始される。
- 進捗表示が段階遷移する。
- 完了時に字幕ブロック一覧へ結果反映される。
- 失敗時にエラー理由が画面表示され、再実行ができる。

## 追記: DAG + Agent SDK 前提のR2拡張計画（2026-04-04）

### 目的

R2時点で直列実装に固定せず、将来の品質チェックループ（意味近似・用語漏れ・ASR二重化）を
段階的に追加できる構造へ移行する。

### 追加マイルストーン

5. M5: DAGランナー化（挙動互換）
- 現在の4工程（書き起こし→補正→翻訳→字幕化）を、DAG Runner上で同じ挙動で実行する。
- `RunState` を導入し、各工程の入力/出力/メトリクスを記録する。

6. M6: 品質ゲートノード追加
- `semantic_check`（原文-翻訳意味近似）
- `terminology_check`（用語漏れ）
- `cps_guard`（決定論チェック）
- NG時の再実行ポリシー（最大回数）を追加する。

7. M7: ASRダブルチェック
- `transcribe_primary` に加えて `transcribe_checker` を追加する。
- `asr_consensus_check` で乖離指標を算出し、閾値超過時はフラグ化する。

### 実装順序（R2内）

1. DAG Runnerの導入（直列互換）
2. semantic/terminology/cps の3チェックを追加
3. ASRダブルチェックを追加
4. Reportタブへノード別情報を表示

### DoD（追加）

- 直列4工程がDAG実行でも同一結果を返すこと
- 品質ゲートで再実行が発生した際、回数と理由がUIで確認できること
- ノード別メトリクス（provider/model/tokens/duration）が履歴に残ること
