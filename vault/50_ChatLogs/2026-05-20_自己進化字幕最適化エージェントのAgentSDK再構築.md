# 自己進化字幕最適化エージェントの Agent SDK 再構築

旧PoC `poc/cps_autonomous_agent_poc.py` を廃止し、`poc/subtitle_agent/`（12モジュール）として再構築した。Phase 0〜4 を実装・検証。

## 後世に残す重要な決定・知見

### 1. 旧PoCの平均類似度 `0.0000` の真因は2つ — 両方とも構造的に解消

- **集計バグ**：`FAILED` 分岐のブロックに `similarity` キーが書き込まれず `0.0` 既定値が混入していた。→ 評価結果を frozen dataclass `EvalResult` で返す設計に変更し、全フィールドが必ず埋まる＝キー欠落が構造的に起こり得ない形にした。
- **意味保持閾値が厳しすぎた**：旧 `0.85` は良訳の約半数を誤却下していた。良訳/悪訳ペアの類似度分布を実測（良訳 median 0.859・p10 0.753／悪訳 median 0.458・p90 0.583）し、データ駆動で **0.67** に較正。
- 教訓：「再実行すれば直る」という引き継ぎは誤り。バグは再現条件ではなくコード構造にあった。

### 2. 評価単位は「ASRセグメント」ではなく「字幕キュー」

ASRセグメントは中央値26秒で、字幕キュー（プロの実務では最長7秒・最短0.83秒、Netflix Timed Text Style Guide）になり得ない。「高密度セグメントは物理的にCPSに収まらない」は誤りで、人間の翻訳者は連続音声を**まずキューに再分割してから**翻訳・凝縮している。再構築版は語タイムスタンプで232 ASRセグメント→965キューに再分割する。

### 3. このデータの語タイムスタンプは無音ギャップがゼロ

WhisperX文字レベル語タイムスタンプの語間ギャップが全て0.0秒。よってキュー間に無音がなく、**retime（時間延長）は機能しない**。CPS遵守の実質的な唯一の手段は**テキスト凝縮**。これは人間の字幕翻訳者の主要技法とも一致する。

### 4. メタLLMは `claude -p` でサブスクリプション認証 — API鍵不要

Claude Agent SDK の Python ライブラリは内部で Claude Code CLI を呼ぶため、ログイン済みサブスクリプションがそのまま使える。PoCのメタ進化は `claude -p` のサブプロセス呼び出しで実装。

### 5. 本番はモデルをAPI経由で差し替える → LLMバックエンド抽象化

本番 `backend/pipeline/nodes/translate.py` は全モデル（OpenAI / Gemini / local）を **OpenAI互換 `/chat/completions` エンドポイント `(base_url, api_key, model)`** として扱う。再構築版も `LLMBackend` プロトコル（OpenAI互換 / claude -p の2実装）で抽象化し、`claude -p` をコードに埋め込まない。

### 6. 検証結果 — 自己進化が実際に機能した

縮小検証（3世代×150キュー）で遵守率 **85.3%→94.7%**（+9.4pt）。旧PoCの10世代フラット（84-86%）とは対照的。プロンプト肥大化も抑制（旧PoCは380→1225字、今回は282→496字）。

## 次セッションの設計合意（`re_segment` 再設計）

「節を細かく刻んで後でmergeする」枠組みは筋が悪い。**最初の分割で意味の塊を作る**。綱引き（意味的coherence vs 時間/文字数制約）の解決方式：

- 強モデル（Claude）が意味の塊で分割候補を複数提案（セグメント長と目標キュー数を渡す）
- コードが各候補を制約スコアで採点 — 日→英の文字数膨張率 k を実測し `推定CPS = k × ja長 / duration` で「凝縮（＝意味損失）をどれだけ強いられるか」を測る
- 役割分担は大原則どおり：**LLM=意味、コード=数値制約の採点**
- スコアに短尺ペナルティ項を追加し、optimizer に merge する勾配を与える（「7秒からの距離」は使わない — 7秒は理想でなく上限）
