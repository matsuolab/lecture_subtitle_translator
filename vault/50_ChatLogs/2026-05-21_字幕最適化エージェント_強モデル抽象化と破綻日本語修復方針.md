# 字幕最適化エージェント — 強モデル抽象化・分割再設計・破綻日本語修復方針

> 2026-05-21 セッション。前日の `poc/subtitle_agent/` 再構築（Phase 0〜4）の続き。
> 計画ファイル: `~/.claude/plans/precious-watching-dahl.md`

## このセッションで実装したもの

- **`LLMBackend` 抽象化** — 強モデル役を差し替え可能に。`OpenAICompatibleBackend`
  （本番モデル・gemma共通）/ `ClaudeCliBackend` / 応答ディスクキャッシュの
  `CachingBackend`。リトライ＋セグメント単位フォールバックで堅牢化。
- **`re_segment` 再設計** — 「強モデルが意味の塊で分割候補を複数提案 → コードが
  推定CPS等で制約採点（`score_candidate`）→ 最良選択」。日英文字数膨張率 k を
  実測（中央値 **1.661**、`measure_expansion.py`）。短尺ペナルティをスコアに追加。
- **分割を自己進化ループから分離** — `optimizer` を `build_cues`（再分割）と
  `optimize_cues`（翻訳・評価・修復）に分割。再分割は世代ループ前に1回だけ実行し
  キュー集合を全世代で固定。進化対象は translate/condense のみ。
- **コスト計測** — `cost.py`。LLM API のトークン利用量を集計し実行末に表示。

## 重要な設計判断

### 1. 分割は自己進化の対象にしない
分割（`re_segment`）を世代ごとに進化させると、世代ごとにキュー集合が変わり
translate/condense の改善効果と分割のブレが混ざって **fitness 信号が濁る**
（3世代テストで遵守率が 91.7%→83.3% とブレた直接原因）。分割の最適化は
別タスクとして切り出す（`docs/ideas.md` I-13）。

### 2. 応答キャッシュは「分割を固定」して初めて意味を持つ
`segment` プロンプトを世代ごとに進化させると応答キャッシュは1実行内でほぼ
ヒットしない。分割を1回固定したことでキャッシュ（実験再実行が即座）が機能する。

### 3. 強モデルを役割で2分割
Claude の使用制限負荷が大きいため本番モデルへ移行。役割で分ける:
- **文章整理**（再分割・日本語校正、高頻度）= `gpt-5.4-mini`
- **改善を考える**（メタ進化、低頻度・要推論力）= `gpt-5.5-2026-04-23`
APIキーは `poc/.env` の `OPENAI_API_KEY`。`run_evolution` は元々
`strong_backend` / `meta_backend` を別引数で受けていたので配線のみで分離可能。

### 4. 破綻日本語の修復は本番準拠で「校正と分割を分離」する
講師の話し方が破綻した日本語（主語述語不整合・逆接/順接の崩れ等）の修復が必要。
本番フロントエンド `frontend/src/lib/pipeline/` を調査して判明したこと:
- **`correct.ts`** が LLM 校正で破綻日本語を修復している（SYSTEM_PROMPT が
  「主語述語の対応を文脈に合わせて整える」「意味が通らない場合は最も尤もらしい
  表現へ修正」を指示。意味・情報量は変えない）。
- **`splitJa.ts`** は決定論的文分割。校正でテキストが変わっても、文の先頭6文字を
  whisperX の word列にプレフィックスマッチして語レベル時刻を回収する**3段階
  アライン**（exact / proportional）を持つ。`alignConf` で精度を記録。
- **`contextMergeFragments.ts`** が翻訳後に文脈マージで断片を処理。

→ 当初検討した「強モデルの分割呼び出しの中で修復する」案（Design A）は本番と
不整合のため**破棄**。校正と分割を分離する方針へ。
詳細調査: `docs/research/20260521_production_pipeline_disfluency_handling.md`

## 次セッションの作業
