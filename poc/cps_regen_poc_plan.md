# CPS自動化 PoC 検証計画

> 作成: 2026-03-31
> 背景: LLMの構造上の問題（トークナイザーが文字数を正確に数えられない）により、
>       15CPS・40文字制約を自動で守った字幕生成ができない。
>       現在は人間が手動調整しており、これを自動化することが目的。

---

## やりたいこと

LLMにツール（文字カウント検証関数）を渡し、自己検証ループで制約を満たすまで
再生成させることで、15CPS制約への自動対応を実現する。

### アイデア①（確立手法）

```
LLM生成 → validate_cps(text, duration) → fail → 再生成 → ...
```

単純なリトライだが、ツールによる自己検証があるため制約を必ず確認できる。

### アイデア②（PoC必要・本命）

```
「どうすれば短くできるか計画を立てよ」
  → LLMが短縮戦略を推論（代名詞化・省略・隣ブロックへの分散など）
  → 計画に基づいて生成
  → validate_cps で検証
  → 失敗なら計画フェーズに戻る
```

盲目的なリトライより翻訳品質・成功率が上がるという仮説。

### 前後ブロックが必要な理由

1. **翻訳精度**: 前後コンテキストがないと意味がずれる
2. **短縮の手段**: 前文で固有名詞が出ていれば代名詞化できる。
   隣ブロックとの関係を利用した短縮が有効なケースがある。

### タイムスタンプ問題の解決方針

前後ブロックへテキストを再配分した場合、
既存の**Diffベースアライメントアルゴリズム**（WhisperX単語タイムスタンプ照合）を
再利用してブロック境界の時刻を再計算する。

## 検証フェーズ

### Phase 1：単一ブロック・ツールループの有効性検証

**問い**: 計画→実行アプローチ（アイデア②）は素朴なリトライ（アイデア①）より有効か？

**実装**:
- ツール: `validate_cps(text, duration) → {chars, max_chars, cps, passed, overflow}`
- A案: 「短くして」→ 検証 → 失敗 → 繰り返し
- B案: 「どう短くするか計画して」→ 計画出力 → 実行 → 検証 → 失敗 → 繰り返し
- 前後ブロックはコンテキストとして渡すが変更しない

**使用データ**: 実データSRTから違反ブロックを抽出

**計測**:
- 成功率（5回以内に制約クリアできたか）
- 平均試行回数
- 翻訳品質（元訳との意味のズレを目視評価）

**判断基準**: B案がA案より成功率・品質で上回るか。上回らなければアイデア②は不採用。

---

### Phase 2：マルチブロック再配分の必要性検証

**問い**: 単一ブロックで解決できないケースはどのくらいあるか？前後分散は有効か？

**実施条件**: Phase 1完了後

**内容**:
- Phase 1の失敗ケースを分析
- 前後ブロックへ意味を分散させれば解決できるか手動確認
- 代名詞化・省略・隣ブロック移動で解決できる代表パターンを抽出

**計測**:
- Phase 1失敗ケース中、前後分散で解決できる割合
- 解決パターンの分類

**判断基準**: 分散で解決できるケースが十分多ければPhase 3へ。少なければ「単体ループ＋人間フラグ」で十分。

---

### Phase 3：マルチブロック＋Diffタイムスタンプ調整の検証

**問い**: テキスト再配分後、Diffアルゴリズムで正確なタイムスタンプが取れるか？

**実施条件**: Phase 2で「前後分散が有効」と判断された場合のみ

**内容**:
- 3ブロックのテキスト再配分をLLMに許可
- 変更後テキスト × 単語レベルタイムスタンプ → Diffアライメント実行
- 新しいブロック境界時刻を計算

**計測**:
- タイムスタンプのズレ量（秒）
- 主観的な視聴確認（字幕と音声のズレが気になるか）

**判断基準**: ズレが許容範囲内かどうか（許容値は中村さん・増田さんへの確認が必要）

---

### Phase 4：統合パイプライン検証

**実施条件**: Phase 1〜3の結果を踏まえ設計確定後

**内容**:
- 確定した方式の end-to-end テスト
- 実データの全違反ブロックに対して実行
- 最終的な「人間が手直しすべき件数」を計測

## ローカルWhisperX先行着手方針

Phase 2/3の検証にはWhisperXの単語レベルタイムスタンプが必要。
AWS Batch（R2正式実装）を待たずに、ローカル環境で先行着手する。

**環境**: RTX 4080（16GB VRAM）→ 大型モデルも動作可能

**先行着手のスコープ**:
- 動画 → 音声抽出
- WhisperX実行 → 単語レベルタイムスタンプ取得
- フロントエンドで結果を受け取るパイプライン

この実装はそのままR2のパイプライン実行タブの核心部分になる。
詳細設計は別途計画。
